# 发布与仓库安全约定

## 源码仓库边界

- `release/`、`build/`、`dist/` 和本地数据目录只保留在本机，不提交到 Git。
- Windows 便携包只通过 GitHub Release 资产分发，不把 exe、ZIP 或动态库提交到源码仓库。
- 应用运行时资源只保留 `src/floating_todo/assets/` 下的一份，避免根目录出现重复副本。
- 临时问题记录、渲染截图、备份目录和本地配置在提交前逐项检查，不进入公开仓库。

## 发布前检查

1. 运行自动化测试、编译检查和 `git diff --check`。
2. 从 ZIP 解压后的新目录启动 exe，确认 `_internal`、`data` 和 `QtWebEngineProcess.exe` 完整存在。
3. 扫描当前跟踪文件和全部可达 Git 历史，检查 API Key、Token、私钥、邮箱、手机号、身份证号、绝对用户路径和异常大文件。
4. 使用 GitHub noreply 邮箱提交，避免公开个人邮箱。
5. 更新 GitHub Release 时，资产文件只放在 Release 中；通过 REST API 写入中文标题、简介或资产标签时，必须使用 UTF-8 字节并在写入后回读验证。
6. 发布后核对远端分支、标签、Release 下载链接、资产数量和文件大小。

## 凭据处理

- 不把 GitHub Token、API Key、密码或私钥写入脚本、文档、日志或命令输出。
- 优先通过 Git Credential Manager 读取现有凭据，只在内存中使用。
- 如果扫描发现真实凭据，先轮换或吊销，再清理 Git 历史并强制更新远端引用。
