# 新建任务快捷交互、历史记录管理与洞察频闪修复设计

## 背景

当前 Windows 桌面 TODO 程序已经支持新增任务、编辑进行中任务、删除进行中任务、历史统计和 3D 任务关系图。本轮在保持现有界面结构和科技风格的前提下，补齐四个高频体验问题：

1. 打开新增任务窗口后，用户仍需额外点击任务名称输入框才能开始输入。
2. 新增任务窗口中的高、中、低优先级预览卡仅用于展示，不能直接点击选择。
3. 历史记录只能编辑备注，不能修改任务名称或删除历史记录。
4. 3D 洞察图持续旋转时，任务关系图图例、Obsidian 风格历史洞察和节点详情三个 HUD 面板存在频闪。

## 目标

- 新增任务窗口打开后，任务名称输入框自动获得焦点。
- 新增任务窗口中的高、中、低优先级预览卡可直接点击选择，并与现有下拉框双向同步。
- 历史记录卡片的更多操作菜单支持修改任务名称和删除历史记录。
- 保留 3D 图谱缓慢旋转效果，同时消除 HUD 面板频闪。
- 保持现有数据结构和便携文件夹存储格式兼容。

## 非目标

- 不在主界面任务卡片中增加新的删除入口。
- 不在 3D 节点详情底部增加改名或删除按钮。
- 不允许通过历史记录编辑入口修改截止时间、工作量、状态或计时数据。
- 不重做历史记录页面布局。
- 不取消 3D 图谱的自动缓慢旋转。

## 方案选择

采用局部增强方案：

- 在现有 `TaskDialog` 中补充焦点管理和可点击优先级卡片。
- 在现有历史卡片更多操作菜单中增加改名和删除动作。
- 在现有 WebEngine HTML 图谱中移除高成本毛玻璃实时合成和节点呼吸脉冲。

该方案改动范围集中，能复用现有存储、刷新和样式体系，不引入新的窗口层级或数据格式。

## 新建任务快捷交互

### 名称输入框首焦点

- 新建任务窗口显示后，`title_input` 自动获得键盘焦点。
- 用户打开窗口后可直接输入任务名称，不需要额外鼠标点击。
- 编辑已有任务时同样将焦点落在名称输入框，并选中现有文本，方便快速替换名称。
- 焦点设置在窗口显示阶段执行，避免构造阶段被后续控件初始化覆盖。

### 优先级预览卡

- 高、中、低三个优先级预览卡由纯展示卡片升级为可点击控件。
- 点击卡片后，将现有优先级下拉框同步切换到对应的 `P1`、`P2` 或 `P3`。
- 下拉框变化时，三个预览卡同步更新选中态。
- 选中卡片使用更明确的边框、背景和状态属性高亮；未选中卡片保持现有视觉层级。
- 下拉框继续保留，用于键盘操作、无障碍访问和兼容现有流程。
- 每张卡片提供指针光标、工具提示和可访问名称。

## 历史记录管理

### 修改任务名称

- 历史记录卡片的更多操作菜单增加“修改任务名称”。
- 点击后显示轻量文本输入对话框，并预填当前任务名称。
- 用户取消时不写入数据。
- 输入内容去除首尾空格后为空时不保存。
- 新名称与旧名称相同时不重复保存。
- 保存后调用现有 `store.save_tasks()`，刷新历史统计、历史记录列表和洞察图。

### 删除历史记录

- 历史记录卡片的更多操作菜单增加“删除历史记录”。
- 删除前显示确认弹窗，明确提示该操作会永久移除历史记录。
- 用户取消时不写入数据。
- 确认后从历史窗口持有的任务列表中移除对应任务，并调用现有 `store.save_tasks()`。
- 删除后同步刷新标签筛选项、分页、历史统计、历史记录列表和洞察图。
- 如果当前页最后一条记录被删除，分页自动回退到有效页。
- 如果目标任务已经不存在，操作直接忽略，不显示错误弹窗。

## 3D 洞察频闪修复

### 根因判断

当前图谱通过 `requestAnimationFrame` 持续绘制 canvas，并在非拖动状态下持续缓慢旋转。与此同时，三个 HUD 面板使用 `backdrop-filter: blur(16px)` 对持续变化的画布背景实时模糊合成，节点还会按时间计算呼吸脉冲。这会增加 Qt WebEngine 的持续合成压力，表现为面板频闪。

### 修复策略

- 保留 canvas 图谱的缓慢旋转。
- 移除 `.glass` 面板的 `backdrop-filter`。
- 保留深色半透明渐变、描边和阴影，延续现有科技风格。
- 移除节点按时间变化的呼吸脉冲，使用稳定半径绘制节点。
- 保留选中节点光晕、超时节点强调、拖动旋转和滚轮缩放。
- 不改变图谱的数据构建逻辑和 Qt WebChannel 通信结构。

## 数据流

### 新建任务

1. 用户打开新增任务窗口。
2. 窗口显示后自动聚焦名称输入框。
3. 用户点击优先级预览卡或操作下拉框。
4. 卡片和下拉框双向同步。
5. 保存时沿用现有 `TaskDialog.build_task()`。

### 历史改名

1. 用户在历史记录卡片菜单中点击“修改任务名称”。
2. 输入对话框返回新名称。
3. 校验通过后使用 `dataclasses.replace()` 替换对应任务。
4. 调用 `store.save_tasks()`。
5. 调用历史窗口渲染流程，必要时重新生成图谱 HTML。

### 历史删除

1. 用户在历史记录卡片菜单中点击“删除历史记录”。
2. 确认弹窗通过后，从任务列表移除目标任务。
3. 调用 `store.save_tasks()`。
4. 重建标签筛选项并刷新统计、分页、记录列表和洞察图。

## 错误与边界处理

- 新建任务窗口首焦点设置失败时，不阻止窗口打开。
- 历史改名取消、空名称或名称未变化时不保存。
- 历史删除取消时不保存。
- 历史改名或删除遇到不存在的任务 ID 时直接返回。
- 删除记录后保留尽可能接近原状态的标签筛选；如果原标签不再存在，则回退到全部标签。
- 图谱频闪修复不依赖 GPU 特性，避免在不同 Windows 图形环境中引入新的运行时要求。
